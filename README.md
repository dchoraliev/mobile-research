# Research Chat App

A React Native mobile app with photo sharing, on-device OCR, and a RAG pipeline backed by FastAPI and SQLite FTS5. LLM integration via OpenRouter is planned for the next phase.

## 1. Backend Setup

### 1.1 Create and activate the virtual environment

```bash
cd Backend
python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # Mac/Linux
```

Always activate the venv before installing packages or running the server. If you skip this step, packages install globally and the server will not find them.

### 1.2 Install dependencies

```bash
pip install -r requirements.txt
```

### 1.3 Download NLTK stopwords (one-time)

```bash
python -c "import nltk; nltk.download('stopwords')"
```

### 1.4 Create the `.env` file

Create a file called `.env` in `Backend/` with your MongoDB connection string:

```
MONGO_URI=mongodb+srv://<username>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority
```

> Never commit `.env` to Git. It is listed in `.gitignore`.

## 2. Knowledge Base Setup

### 2.1 Add documents to `docs/`

Drop `.txt` or `.pdf` files into `Backend/docs/`. These are the documents the RAG pipeline will search when users ask questions about photos.

Example documents to get started:
- A product manual as a `.txt` file
- A set of notes or reference sheets as `.txt` files
- Any PDF with searchable text

### 2.2 Ingest documents into SQLite

```bash
python ingest.py --source ./docs
```

This chunks each document into 500-character overlapping pieces and stores them in `knowledge.db`. Re-running is safe — existing chunks for a file are replaced. Run this again whenever you add or update documents.

## 3. Running the Backend

```bash
uvicorn main:app --reload --port 8089
```

For WebSocket-only testing without the full server:

```bash
uvicorn echo:app --reload --port 8089
```

> Do not run both at the same time — they use the same port.

## 4. Exposing the Backend to Your Phone (ngrok)

Since the app runs on a physical device, you need to tunnel your local server. Install ngrok from [ngrok.com/download](https://ngrok.com/download), then:

### 4.1 Link your ngrok account (one-time)

```bash
ngrok config add-authtoken YOUR_TOKEN_HERE
```

Get your token from [dashboard.ngrok.com](https://dashboard.ngrok.com/get-started/your-authtoken).

### 4.2 Start the tunnel (separate terminal)

```bash
ngrok http 8089
```

You will see a forwarding URL like:

```
https://your-subdomain.ngrok-free.app -> http://localhost:8089
```

Copy the subdomain for the next step. Note that ngrok generates a new subdomain each session on the free tier — update `config.js` each time.

## 5. Frontend Setup

### 5.1 Install dependencies

```bash
cd Frontend
npm install
```

### 5.2 Install expo-text-recognition

```bash
npx expo install expo-text-recognition
```

This provides on-device OCR using ML Kit (Android) and Vision Framework (iOS). No ejecting required.

### 5.3 Configure `config.js`

Open `Frontend/config.js` and paste your ngrok subdomain:

```js
const NGROK = "your-subdomain.ngrok-free.app";
const LOCAL_HTTP = `https://${NGROK}`;
const LOCAL_WS   = `wss://${NGROK}/ws`;
const USE_LOCAL  = true;
```

For production set `USE_LOCAL = false`. `PROD_HTTP` and `PROD_WS` already point to the Render deployment.

## 8. How the RAG Pipeline Works

1. User takes a photo — OCR runs on-device automatically using `expo-text-recognition`
2. A system message confirms how much text was detected
3. User types a question — this triggers a `POST /search` request instead of a chat message
4. The backend combines the question and OCR text, extracts keywords using NLTK, and queries the SQLite FTS5 knowledge base
5. Matching chunks are displayed in chat with their source filename
6. A note confirms that LLM integration is coming in the next phase

To cancel the RAG flow and return to plain chat, tap the **✕ Clear** button that appears after taking a photo.

## 9. API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/` | Health check |
| `WS` | `/ws` | WebSocket chat (broadcast to all clients) |
| `POST` | `/upload-photo` | Upload a photo, returns URL |
| `GET` | `/photos` | List all uploaded photos |
| `POST` | `/search` | RAG search — accepts `query` and `ocr_text` |

## 10. .gitignore

The following should be in your `.gitignore`:

```
venv/
__pycache__/
.env
*.db
*.pyc
.expo/
```

To track the `docs/` folder without committing its contents:

```gitignore
# Ignore all .txt files except those in Backend/docs/
*.txt
!Backend/docs/*.txt
```

Place a `.gitkeep` file inside `docs/` so the empty folder is tracked:

```bash
type nul > Backend/docs/.gitkeep    # Windows
touch Backend/docs/.gitkeep         # Mac/Linux
```

## 11. Deploying to Render

1. Push your `Backend/` code to GitHub
2. Create a new **Web Service** on [render.com](https://render.com)
3. Set the build command to: `pip install -r requirements.txt`
4. Set the start command to: `uvicorn main:app --host 0.0.0.0 --port 8089`
5. Add `MONGO_URI` as an environment variable in the Render dashboard
6. Set `USE_LOCAL = false` in `config.js`
